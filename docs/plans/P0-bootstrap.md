# P0 — Bootstrap repo, tooling, CI, release

Status: todo · Owner: coordinator agent + maintainer · Branch: `main` (initial commits)

## Goal

An empty-but-releasable package: tooling configured with official commands, all scripts working,
CI green, release workflow in place, `eharness@0.0.1` placeholder published manually and the npm
trusted publisher configured.

## Specs / docs

- `docs/architecture.md` §2 (package & exports)
- `docs/engineering/conventions.md` (toolchain)
- `docs/engineering/release.md` §4 (one-time setup)
- ADR-0007, ADR-0009, ADR-0010

## Owns

Everything at the repo root, `scripts/`, `.changeset/`, `tsdown.config.ts`, `biome.json`,
`tsconfig.json`, placeholder `src/**/index.ts` files.

## Already in the repo (do not regenerate)

`CLAUDE.md`, `README.md`, `CONTRIBUTING.md`, `docs/**`, `.github/**` (workflows, dependabot,
templates).

## Checklist

**Rule:** before running each command, open the tool's official documentation and use the current
command/flags. Never hand-write a file the tool generates.

1. [ ] `bun init -y` in the repo root. Keep the existing `README.md`/`CLAUDE.md` (if `bun init`
   creates or edits agent rule files such as `CLAUDE.md` or `.cursor/`, revert those changes).
   Delete the generated entry file (`index.ts`).
   **Then remove what `bun init` adds for apps but breaks a library:** `"private": true` (makes
   `npm publish` fail and Changesets skip the package), `"module": "index.ts"`, and
   `peerDependencies.typescript`.
2. [ ] Dev dependencies (latest stable at the time):
   `bun add -d typescript tsdown @biomejs/biome publint @arethetypeswrong/cli @changesets/cli @changesets/changelog-github @types/bun ai zod @ai-sdk/mcp`
3. [ ] `bunx biome init`, then set: 2-space indent, `lineWidth: 100`, single quotes,
   `semicolons: "asNeeded"`, ignore `dist/`, `coverage/`, `.changeset/*.md`.
4. [ ] `bunx changeset init`, then edit `.changeset/config.json` exactly as in release.md §4.2
   (`access: public`, `changelog-github` with the real `OWNER/eharness`, `changedFilePatterns`
   including the test/golden exclusions).
5. [ ] Edit `package.json` (fields, not a regenerated file). Pin `@types/bun` to the installed
   version instead of `latest`.
   ```jsonc
   {
     "name": "eharness",
     "version": "0.0.1",
     "description": "Build your own agent harness on AI SDK v7: plugins, context, messages, streaming, sessions, compaction.",
     "type": "module",
     "license": "MIT",                       // confirm with maintainer (open question)
     "repository": { "type": "git", "url": "git+https://github.com/OWNER/eharness.git" },
     "homepage": "https://github.com/OWNER/eharness#readme",
     "bugs": "https://github.com/OWNER/eharness/issues",
     "keywords": ["ai", "ai-sdk", "agent", "harness", "llm", "tools", "skills", "mcp"],
     "sideEffects": false,
     "engines": { "node": ">=22" },
     "packageManager": "bun@<installed version>",
     "files": ["dist"],
     "publishConfig": { "access": "public" },
     "peerDependencies": { "ai": "^7.0.0", "zod": "^3.25.76 || ^4.1.8", "@ai-sdk/mcp": "^2.0.0" },
     "peerDependenciesMeta": { "@ai-sdk/mcp": { "optional": true } },
     "scripts": {
       "lint": "biome check .",
       "format": "biome format --write .",
       "typecheck": "tsc --noEmit",
       "test": "bun test",
       "build": "tsdown",
       "check:package": "publint && attw --pack . --profile esm-only",
       "check:imports": "bun scripts/check-imports.ts",
       "release:version": "changeset version && bun install --lockfile-only"
     }
     // "exports" is generated by tsdown (step 7) — do not hand-write it
   }
   ```
6. [ ] `tsconfig.json` (edit the generated one): `target: ES2023`, `module: preserve`,
   `moduleResolution: bundler`, `strict`, `isolatedDeclarations: true`, `declaration: true`,
   `verbatimModuleSyntax`, `noUncheckedIndexedAccess`, `skipLibCheck`,
   `lib: ["ES2023", "DOM", "DOM.Iterable"]`, `types: ["bun"]`,
   `include: ["src", "examples", "scripts"]`, and
   `paths: { "eharness": ["./src/index.ts"], "eharness/*": ["./src/*"] }` so in-repo
   `declare module 'eharness'` augmentations and examples resolve to source, not `dist/`.
   Verify TypeScript 7 works with tsdown's dts path (isolated declarations) and with attw; if not,
   pin the TypeScript major that does and note it in conventions.md.
7. [ ] `tsdown.config.ts`:
   ```ts
   import { defineConfig } from 'tsdown'
   export default defineConfig({
     entry: {
       index: 'src/index.ts',
       'filesystem/index': 'src/filesystem/index.ts',
       'filesystem/memory': 'src/filesystem/memory.ts',
       'storage/memory': 'src/storage/memory.ts',
       'mcp/index': 'src/mcp/index.ts',
       'testing/index': 'src/testing/index.ts',
     },
     format: 'esm',
     platform: 'neutral',
     dts: true,
     exports: true,
   })
   ```
   Run `bun run build`; **verify** the generated `exports` has exactly `.`, `./filesystem`,
   `./filesystem/memory`, `./storage/memory`, `./mcp`, `./testing`, `./package.json`. Adjust entry
   names or `customExports` until it does. Peer deps must stay external (check `dist/`).
8. [ ] Placeholder sources so every entry builds: `src/index.ts` exports a `HarnessError` stub and a
   `version` const; each subpath file exports `experimental_placeholder` with TSDoc
   `@experimental Not implemented yet.` (conventions: experimental names carry the prefix).
9. [ ] `scripts/check-imports.ts`: fail if any file under `src/filesystem|storage|mcp|testing`
   imports from core by any path other than the relative path to `src/index.ts`; fail if any
   non-test file under `src/` contains `Bun.` or imports `node:`.
10. [ ] `scripts/smoke.mjs` (plain Node ESM, run by CI in a clean project): import every subpath,
    assert expected exports exist (grows with each phase; from P2 on also runs one scripted turn
    with `MockLanguageModelV4` against `memoryMessages()`). With `--no-mcp` it runs without
    `@ai-sdk/mcp` installed and asserts that importing `eharness/mcp` still works (from P6 on:
    that an eager `mcpServer` fails with `EH_CONFIG_INVALID`).
11. [ ] `.gitignore`: add `dist/`, `coverage/`, `*.tgz`.
12. [ ] `LICENSE` file matching `license` (after maintainer confirmation).
13. [ ] All scripts green locally: lint, typecheck, test (one trivial test), build, check:package,
    check:imports. Commit: `chore: bootstrap repository`.
14. [ ] Push; CI green on `main`. The Release workflow is skipped (repository variable
    `RELEASE_ENABLED` is not set yet) — expected.
15. [ ] **Maintainer:** release.md §4 steps 1–7 in order: repository settings (environment `npm`
    with branch policy, release GitHub App), first manual publish of `0.0.1`, trusted publisher,
    disallow tokens, then `RELEASE_ENABLED=true`.

## Acceptance criteria

- [ ] Fresh clone → `bun install && bun run build && bun run check:package` passes.
- [ ] `npm pack` tarball contains only `dist/**`, `package.json`, `README.md`, `LICENSE`.
- [ ] CI `check` and `node-compat` (22, 24) green.
- [ ] `npm view eharness` shows `0.0.1`; trusted publisher configured for `release.yml` / env `npm`.
- [ ] A test PR with a changeset produces a "chore(release): version packages" PR after merge, CI
      runs on that PR (GitHub App token), and merging it publishes `0.0.2` with provenance and a
      `v0.0.2` tag + GitHub release (end-to-end test of the pipeline).
