New subpath `eharness/connectors` (spec 24, ADR-0049..0052; Draft): connector definitions (with optional display metadata `publisher`, `homepage`, `docsUrl`; `toolPrefix: 'always' | 'multiple' | 'never'` controls the connection-slug tool prefix), connections (workspace or agent scope, stored as `ConfigProfile` rows of kind `connection` with OAuth credentials in a separate row; `ConnectionRecord.slug` is an optional stable tool-prefix slug, so renaming a connection never renames its tools), per-agent enablement with capability modes (`allow | ask | off`) and per-tool overrides, a server-driven setup flow engine with a closed view vocabulary (`startFlow`, `advanceFlow`, `completeOAuth`, stale-view guard, sealed scratch; `FlowStepContext.label` titles the OAuth and device-code views with the connection's label), OAuth 2.1 helpers (PKCE, RFC 9728 / 8414 discovery, dynamic client registration, code exchange, refresh under a lock, device grant; `clientConfig(definitionId, flow)` receives the asking flow and the connection's `settings`, for per-connection OAuth clients), `activateConnectors` (stable plugin order, tool prefixes for several connections, permission rules with pinned asks that bypass mode cannot skip), `createConnectorService`, built-in connectors for the shipped plugins (`builtinConnectors`, `ensureBuiltinConnections`) and a custom remote MCP connector (`remoteMcpConnector`). It builds on the `SecretVault` of `eharness/providers`. `eharness/mcp` gains `remoteMcpSource` (fresh bearer per request), `bearerAuthProvider` and `listRemoteMcpTools`. `eharness/testing` adds `connectionStoreConformance`, `credentialStoreConformance`, `enablementStoreConformance` and `flowStoreConformance`.
