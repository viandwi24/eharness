Nothing the core awaits can hang a turn forever. Every awaited plugin hook is raced against the turn abort signal and `hooks.timeoutMs` (default 30 000; `W_HOOK_TIMEOUT`, `input.submit` stays fail-closed, `tool.approve` still denies); model streams get a default idle timeout (`settings.timeout` `firstChunkMs`/`chunkMs` 120 000, `timeout: false` turns it off) and an explicit `maxRetries` of 2; `mcpServerSource` connect and tool listing time out after `timeoutMs` (default 15 000, `EH_MCP_TIMEOUT`); tool sources are listed concurrently with a `toolSources.timeoutMs` limit and a backoff for failed sources (`toolSources.retryAfterMs`); every OAuth token, refresh, registration and discovery request has a default 15 000 ms limit. **BREAKING:** a failed tool source is no longer retried at every turn (set `toolSources: { retryAfterMs: 0 }` for the old behaviour); an `input.submit` hook that throws now blocks with the generic text `Input check failed.` instead of the error message. The default logger prints errors as name, message, code, status and cause only (no request bodies, headers or URL queries). Tests now fail on `W_INVARIANT_VIOLATION`.
