One glob compiler and one path normalisation. The five glob and gitignore compilers (`glob` tool, permission rules, `diskFs` ignore files, OpenAPI path filters, provider model filters) now share one core compiler (`compileGlobRegExp`, `compileGitignorePattern` with the options `dot`, `gitignore`, `caseFold`; also `collapseSegments`, `normalizeRootedPath`, `foldSegment`, `escapeRegExp`, `statelessPattern`, `unsafePatternReason` exported from the core), and the filesystem, memory and permissions path helpers share `collapseSegments`. Matching is unchanged for every pattern we compared before and after, except: consecutive `**` collapse, a pattern with more than 4 `**` segments or 8 `*` wildcards is refused (`glob` tool: `ERROR: invalid pattern`; a permission rule or ignore line that cannot compile never matches; an OpenAPI path filter throws `EH_CONFIG_INVALID`; a provider model pattern falls back to equality). This fixes a ReDoS: `**/` repeated ten times took 427 ms per path and the `glob` tool is auto-approved. Fixed: `a//b` in a gitignore line no longer matches a literal double slash (empty segments are skipped like in `diskFs` ignore files), and trailing spaces of a case-insensitive permission pattern are dropped like in the case-sensitive one. Fixed: `hiddenPrefixes` and `readonlyPrefixes` of the filesystem tools are compared case-insensitively on NFC-folded segments, like the permissions engine, so `/Secrets` is hidden when `/secrets` is.
