New subpath `eharness/code` (Draft, spec 28, ADR-0061): `code()` lets an agent run Python over the files of the virtual file system. The file system stays the source of truth; the sandbox directory is a per-session cache synced incrementally before and after every run, with compare-and-set write-back (a file changed meanwhile is reported as a conflict instead of overwritten) and managed Python packages. The `filesystem()` plugin now provides a `filePolicy` service (`isHidden`, `isReadonly`, `extensionAllowed`, `isUndeletable`, built from the same options as the file tools) so sync honours the hidden, read-only, extension and undeletable rules; the `FilePolicy` type is exported. The built-in `files` connector gains optional code capabilities (`files: { code: true | { install: true } }`): `run` (`run_python`) and `install` (`install_packages`), both defaulting to `ask`. The local shell sandbox also gains `denyRead` / `denyReadHome` / `allowRead` (read isolation), resource `limits` (CPU, file size, memory on Linux, processes) and `scratchSandbox` / `removeStaleScratch` (a disposable work directory per session). The OS sandbox is defence in depth; use a container or VM driver for hostile code.
